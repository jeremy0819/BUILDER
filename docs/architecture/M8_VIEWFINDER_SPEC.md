> **狀態**：規格草案 → 待使用者核准

## 0. 憲章（一句話）

> **M8 — THE VIEWFINDER**：讓整合人**看見**案子的形狀、差異與敏感度，
> 而**看見的動作永不改變案子**。
> 觀景窗的定義就是：你透過它取景，但它不在底片上作畫。

### 0.1 為什麼叫觀景窗，不叫畫布

「Canvas（畫布）」隱含作者權——使用者在上面畫，內容因此誕生。那正是本里程碑
**最危險**的失敗模式：一旦圖可以被拖出新數字，UI 就長出了第二套計算，
直接違反「公式只有一份」的紅線。

觀景窗不同：它有取景、對焦、切換鏡頭（互動），但**成像來自被拍的東西**。
M8 的每一個像素都必須追得回 Core 的某個欄位。

### 0.2 一條分界線，決定 M8 的成敗

```
可拖曳的只有 Input；Output 永遠唯讀。
```

- 拖滑桿改「住宅單價」→ 合法（那是輸入，改完向 Core 重算）。
- 拖量體長高改「容積」→ **違規**（那是 Core 的輸出，反拖即反算）。
- 拖瀑布圖的長條改「貢獻度」→ **違規**（歸因是 Core 的結論，不是輸入）。

> 這條線是 M8 版的「只記事實，不記推論」。實作上以回歸測試釘死（見 §8 Case C）。

## 1. 在五層堆疊的位置

M8 **不是第六層**。它是把既有 Presentation 層加厚——正因為加厚，紀律要更嚴。

```
Core（事實・SSOT）
   ▼
Workflow ＋ Memory（M7）
   ▼
Decision Engine（判讀・M4）
   ▼
Strategy Engine（建議・M6）
   ▼
Presentation（呈現・零推論）  ← 【M8 在這裡加厚，權威不變】
```

### 三條鐵律

1. **零計算**：圖層不得出現任何領域算術。唯一允許的算術是**版面幾何**
   （比例縮放、座標映射、色階插值），且不得回寫成領域數值。
   > 判準：把這行程式碼刪掉，會不會少一個「數字」？會 → 違規；只會少一個「位置」→ 合法。
2. **零來源不畫**：每個可見數值必須綁定 Core 欄位路徑，並登記於 `UI_BINDING_MAP.md`。
   取不到來源就顯示「—」與原因，**不得留白讓人自行腦補**。
3. **不確定性不得被美化抹除**：未校準、示意、待複核的數字，在圖上必須與在表格上
   一樣顯眼。圖比表更容易讓人相信——所以標示責任更重，不是更輕。

## 3. M8.1　視覺語彙與圖表契約（先做，別急著畫）

比照 M4／M6／M7 的成功路徑：**Schema First**。先定「一張圖被允許說什麼」，再畫。

### 3.1 Chart Contract

每個圖表宣告一份契約（不是新 schema 檔，而是圖層的宣告物件）：

```json
{
  "chart_id": "attribution-waterfall",
  "series": [
    { "field": "presentation.contributions[].impact",
      "source": "attribution-0.1", "unit": "ppt", "higher_is_better": true }
  ],
  "must_not_read_as": ["時序", "因果強度", "IRR"],
  "uncertainty": { "level": "calibrated|directional|illustrative", "note": "…" },
  "empty_reason": "兩個方案沒有可歸因的 params 差異"
}
```

- `must_not_read_as` 是本專案特有的欄位，把「這張圖最容易被誤讀成什麼」寫進契約，
  並在 UI 上以說明文字呈現。**誤讀的防線要進契約，不能只靠設計師記得。**
- `uncertainty.level` 三態直接對應既有紀律：已校準／方向性判斷／示意。

### 3.2 統一視覺語彙

沿用既有設計 token，不另立系統：

| 元素 | 規則 |
|---|---|
| 數值欄 | 等寬數字（tabular numerals）、右對齊、單位不換行 |
| 正負 | 顏色 **＋** 正負號 **＋** 文字，三者齊備；**顏色不得為唯一編碼** |
| 好壞方向 | 由 `higher_is_better` 決定，不由顏色慣例決定 |
| 不確定 | 斜線填充／虛線邊框＋明文標籤，不得只靠淡化 |
| 空狀態 | 顯示「為什麼沒有圖」，不顯示裝飾性空圖表 |

## 4. M8.2　歸因瀑布圖（價值密度最高，建議優先）

M7.4 交付的是**表格**；交付計畫的線框要的是**瀑布圖**。這是 M8 最直接的補完。

```
全案投報率                                    [Shapley 精確]
51.50%  ┤                                              56.94%
        │  ┌─────┐                                        │
        │  │+5.71│ 住宅單價  65.0 → 68.25                  │
        │  └─────┘  ┌──┐                                   │
        │           │-0.27│ 車位數  78 → 76                │
        │                  ┌┐                              │
        │                  ││ 交互作用（殘差）  0.00        │
        └──────────────────────────────────────────────────┘
        顯示加總 +5.44 ppt ＝ 實際變化 +5.44 ppt   [守恆 ✓]
```

**必要互動**

| 互動 | 行為 | 權威 |
|---|---|---|
| hover／鍵盤 focus 長條 | 高亮對應的變更欄位列，展開前後值 | Core 回應 |
| 點選長條 | 展開證據：正規路徑、法源、輸入來源、資料版本 | Core 回應＋法源包 |
| 切換基準／對照 | 前次結果標記 stale 並隱藏，不沿用 | UI 狀態 |
| **拖曳長條** | **不存在**——貢獻度是 Core 的結論，不可被拖 | — |

**必要標示（缺一不可）**

- 排序依影響絕對值，**不是變更時序**；不得用箭頭或動畫暗示先後。
- 殘差列與貢獻列**同等視覺權重**，永不摺疊到摺線下方。
- OAT 時明示「近似」，並讓殘差更顯眼。
- 顯示進位對帳（`rounding_reconciliation`）非零時獨立成列，**不得併入殘差**。

## 5. M8.3　互動量體（M7.5 的升級）

M7.5 已有逐層長條與明細表。M8.3 升級為可檢視的量體：

- **軸測圖**（axonometric）由 `floors[]` 逐層堆疊；點選任一層 → 高亮並跳到明細列。
- 地上／地下／屋突／停用層以既有樣式區隔；停用層**顯示但不隱藏**。
- 免計項（梯廳／安全梯／陽台）可切換疊加，數值一律讀 `floors[]` 原值。

**絕不做**

- ❌ 拖曳量體改高度／面積（＝反算容積，紅線）
- ❌ 由圖推導任何 Core 沒給的數字（如自行加總樓地板）
- ❌ 真 3D 建模（引入依賴且無決策價值）

> 判準沿用 M7.5：長條寬度是**版面幾何**，不是容積；合計只從 Core `result` 取，
> 取不到顯示「—」。

## 6. M8.4　敏感度地圖（誠實度要求最高的一項）

兩個參數掃描 → 熱區圖，疊上既有門檻等值線（如**融資閘門共負比 70%**）。

```
        營造單價 →
住   ┌───────────────────────┐
宅   │ ░░░▓▓▓███████████████ │   ███ 共負 >70%（融資閘門外）
單   │ ░░░░░▓▓▓▓▓███████████ │   ▓▓▓ 65–70%（貼近閘門）
價   │ ░░░░░░░░▓▓▓▓▓▓███████ │   ░░░ <65%
↓    └───────────────────────┘
     每一格＝一次真實 Core 重算（11×11 ＝ 121 次）
```

**這一項最容易造假，故紀律最嚴：**

1. **每格必須是真實 `recompute`**，不得以插值填滿。
2. 若因效能而降低網格解析度，**必須顯示實際網格數**（如「11×11」），
   讓使用者知道等值線的解析度極限。
3. 等值線若經平滑處理，**必須標示為視覺平滑**，且不得用於判讀是否跨越門檻——
   跨閘門與否一律回到該格的 Core 數值。
4. 計算量大 → 採**明確按鈕**觸發並顯示進度，不做拖曳即時掃描
   （沿用 M7.4「精確 Shapley 用按鈕不用自動執行」的同一判斷）。

> 為什麼嚴：一張漂亮的漸層圖會讓人以為每一點都算過。若其實只算了 25 格再插值，
> 那條 70% 等值線就是**畫出來的，不是算出來的**——而使用者正要拿它決定要不要掏錢。

## 7. M8.5　GIS 疊圖（被離線圖資決策卡住）

M7.5 已明文延後，原因不變：**外部圖磚違反「單一自含 HTML、零依賴、零 CDN、可離線」的靜態純度紅線。**

三個選項，需使用者裁決：

| 選項 | 做法 | 代價 |
|---|---|---|
| A. 自帶向量圖磚 | 只打包案件周邊極小範圍的向量圖資進 repo | 圖資授權須確認；repo 體積；**更新責任落在自己** |
| B. 政府開放圖資本地化 | 由使用者本機匯入（比照 File System Access） | 每案手動一次；但**零版控風險、零依賴** |
| C. 不做 | 以既有的基地條件表格取代 | 失去空間直覺，但省下整條依賴鏈 |

> ⚠️ 無論選哪個，**真實地籍圖資都不得進版控**——那是 Gate 0 結構式守衛
> （`tools/check_real_data_patterns.py`）與圖檔白名單（Gate 8）共同守的線。
> 我的建議是 **B**：與 M7 的 Local-first 策略一致，把資料留在使用者機器上。

## 8. 對抗性回歸（CI Gate）

```
Case A · 圖層零計算
  掃描 M8 圖層原始碼 → 不得出現領域算術（容積／共負／投報／坪效）
  亦不得 import 任何計算模組；唯一允許的是版面幾何

Case B · 每個系列可溯源
  每張圖的每個 series 必須有 field＋source，且能在 UI_BINDING_MAP 找到對應列
  找不到 → 測試紅

Case C · 拖曳只動 Input ★
  對 Output 欄位發出拖曳／編輯事件 → 必須被拒絕且不改變任何狀態
  這是 M8 的核心不變式

Case D · 不確定性不得被抹除
  uncertainty.level != "calibrated" 的圖 → DOM 中必須存在可見標示

Case E · 無障礙
  每個資料點鍵盤可達；顏色非唯一編碼（移除顏色後資訊不遺失）
  長標籤／負值／零值／窄螢幕不破版

Case F · 靜態純度
  頁面零外部請求（無 CDN／外部字型／遠端圖磚）

Case G · 敏感度地圖不得插值冒充
  宣告網格數 N×M → 實際 recompute 呼叫次數必須等於 N×M
```

## 9. 交付順序

```
M8.1 圖表契約與視覺語彙   先定「圖能說什麼」，再畫（Schema First）
M8.2 歸因瀑布圖           補完 M7.4 線框；價值密度最高，建議優先
M8.3 互動量體             升級 M7.5，讀既有 floors[]
M8.4 敏感度地圖           計算量大、誠實度要求最高，放後面
M8.5 GIS 疊圖             卡在離線圖資決策，可獨立插入或不做
```

> 順序理由：M8.1 是其餘各項的共用地基；M8.2 有現成的 Core 輸出（`presentation`）
> 可直接餵，不需新 Core 能力，因此見效最快；M8.4 需要新的批次重算路徑，成本最高。

## 11. 明確不做（邊界）

- ❌ **拖曳 Output**（拖量體改容積、拖長條改貢獻）——第二套計算，紅線
- ❌ 引入圖表框架／繪圖庫／CDN／外部字型（破壞靜態純度）
- ❌ 真 3D 建模工具、量體設計功能
- ❌ 以動畫暗示因果或時序（歸因排序非時序，已明訂）
- ❌ 以顏色作為唯一編碼
- ❌ 敏感度以插值冒充實算
- ❌ 真實地籍圖資進版控
- ❌ AI 生圖／自動視覺化建議（護城河是決策模型，不是 AI）

## 附錄 · 為什麼 M8 的紀律要比前面更嚴

M4 給了判讀，M6 給了建議，M7 給了記憶與歸因——那些都是**文字與數字**，
讀者天然會保持懷疑。

圖不一樣。**一張圖會先被相信，才被檢查。**漸層讓人以為連續、平滑讓人以為算過、
動畫讓人以為有先後。M8 把說服力放大了一個量級，所以：

> 前面幾個里程碑守的是「算得對」與「說得清」；
> **M8 守的是「看起來對，而且真的對」。**

這也是為什麼本規格把「不確定性不得被美化抹除」與「敏感度不得插值冒充」
寫成硬性回歸，而不是設計建議——因為它們一旦鬆掉，沒有人會發現。
