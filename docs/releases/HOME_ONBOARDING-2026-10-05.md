## 主管摘要

首頁新增基地、財務、地主與決策用途圖示，建案入口以大數字清楚區分三個階段：
**1 填寫條件、2 檢視初評、3 儲存案件**。
建案完成後才進入既有四步工作；回訪者仍優先看到案件續做，不重新經過新手流程。
介面沒有增加頁面、彈窗或新資料庫。

## 互動狀態

| 情境 | 建案提示 | 資料行為 |
| --- | --- | --- |
| 初次開啟／背景 Core 重算完成 | 第 1 步，初評待檢視 | 不建立案件 |
| 明確按快速評估 | 第 2 步，本次 Core 結果 | 唯讀預覽，下一個主動作為儲存 |
| 修改欄位／重設 | 回到第 1 步，舊初評失效 | 不採用舊數字 |
| 確認儲存 | 第 3 步，完成後進①基地 | 沿用 CaseBus 建案契約 |
| Core 無法使用 | 初評尚未計算，可先儲存輸入 | 保留 pending 指紋，結果未知，不補零 |
| 儲存失敗 | 返回輸入／檢視狀態，可重試 | 輸入保留，已存案件不變 |
| 調整既有案件 | 隱藏新增案件三步提示 | 既有 ID 不變，採用前仍是預覽 |

未儲存的四步預覽不提供跳頁連結，避免新草稿誤進舊案件。
新增案件的首頁、工作區與產品缺資料入口明確使用 `?new=1#entry`，不與編輯混用。

## 一併修正的邊界

- 自建第一個案件後不再自動補入四個示範案；只有已明確索取的示範集合才升級。
- 示範集合更新保留使用者案件、附件與紀錄，不清除既有資料。
- 新案件的預設 ID 若命中已存案件，僅該新案以 `crypto.randomUUID()` 配置合法 `prj-` ID。
- 相同輸入仍有相同 Core 指紋，但可以是不同案件；不覆寫舊案件，不遷移舊 ID。
- 儲存空間不足／儲存遭封鎖時提供人可讀的錯誤與重試，不把輸入當成已儲存。
- input-only 重試不會被誤當成已完成 Core 初評。
