# BUILDER PM Workflow P0（2026-10-01）

本輪把公開版收斂為「都更開發案的決策工作台」。首頁先回答目前案件、可辨識的問題與下一步；四步工作區保留既有資料權威與重算流程。這是 UI／資訊架構更新，不變更 Core、Schema 或 OS Release 版本。

## 已交付

| PM P0 | 使用者行為 |
| --- | --- |
| 回訪首頁 | 有作用中案件時先顯示案件卡與下一步，建案表單收起；沒有案件時顯示四欄快速評估。初步 Core 結果可先看，確認後再儲存。 |
| 下一步 | 首頁與案件總覽顯示可由已存資料辨識的提醒和可前往的入口；四步頁保留各自的操作引導。 |
| 四步名稱 | 改為「基地與法規／產品與財務／地主整合／策略決策」，不改資料鍵與路由。 |
| Dashboard 身份 | `dashboard.html` 在 UI 中稱為基地與法規工作區；`overview.html` 是每日案件總覽。 |
| Decision readiness | 產生分析前逐項說明案件、可重算輸入、Core、本機草稿與計算中狀態。結果把引擎判定及最多三項策略行動放在證據圖前。 |
| People 分工 | 正式逐戶紀錄為預設主畫面；合成策略沙盤經獨立入口與 `?tool=simulation` 開啟，回到紀錄不修改案件事實。 |

## 資料與呈現邊界

- 所有財務比率和面積取自 CaseBus 的 Core 結果或快照；同意數取自既有事件或快照，並標示來源。沒有資料顯示「—」。
- 首頁的「需核對」只依缺少輸入、舊版快照、缺失雜湊、Core 提醒及同意快照來源產生。這不是法規門檻、信心分數或資料新鮮度判定。
- Decision 的判定與逐戶行動只取本次 Decision／Strategy 回應。未儲存分析結果回案件快照；未提供負責人和期限時不臆測。
- 3D 仍是明示的合成場景工具，不代表本案建築輪廓、法定 LOD 0、逐層幾何或地主選配。正式幾何來源與契約仍待核准。
- `uros.last_step.<pid>` 只記本機導覽偏好，沒有納入案件備份，也不是案件歷程。

## 後續範圍

方案比較、Today／Changed／Blocked、逐步完成度與資料新鮮度、會議 PDF、任務負責人與期限屬 P1／P2；需要相應的方案、活動與治理資料契約後再做，不能以 UI 預設值填補。
